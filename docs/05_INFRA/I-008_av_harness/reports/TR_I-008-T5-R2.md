## Step 4 — F6 root cause + fix + contact-frame proof

### Root cause (bezier display-replay before fix)

`tools/bounce-view/playback.cpp` and `scene.cpp` bezier event-replay branches (pre-fix):

```cpp
const auto contact_pos = bounce::core::engine::position_at_time(state, dt);
state.x0 = contact_pos.x;
state.y0 = contact_pos.y;
```

For polynomial curves the replay path sets `state.x0 = event.s` and `state.y0 = eval(curve, event.s)`,
snapping each arc origin onto the drawn curve. For bezier, the pre-fix path reused the ballistic
endpoint from `position_at_time` instead. That Cartesian point is engine-correct for physics but can
lie off the display curve polyline: the renderer samples bezier segments in segment-parameter space
while the inverted-x helper `locate_bezier_display_point` maps world contact *x* (`event.s` for
bezier collisions) to segment coordinates. Replaying ballistic endpoints without snapping to
`eval_bezier_at_contact_x(curve, event.s)` lets the drawn ball drift through the drawn curve over
many contacts while audio (a pure function of engine events) stays rhythmic — F6.

### Fix (display-only; S1 respected)

Added `eval_bezier_at_contact_x` in `bezier_display_geometry.{hpp,cpp}` (display-only). Bezier
replay now snaps arc origins exactly as polynomial replay snaps `y`:

```cpp
const auto curve_pos = eval_bezier_at_contact_x(pb.scenario.piecewise_bezier, event.s);
state.x0 = curve_pos.x;
state.y0 = curve_pos.y;
```

Engine data consumed (`event.s`, normals); no physics computed in the harness.
